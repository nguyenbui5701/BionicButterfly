# BionicButterfly — State-Machine Edge Cases & No-Event Evaluation (Design Oracles)

- **ID:** BB-P25-TEST-095 | **Version:** 0.1 | **Status:** TEST DESIGN ONLY; P25-T01–T16 **NOT RUN**.
- **Dependencies:** `84–87`, `67`, Phase25 `93–94`; numeric values are candidate SIM-only, not flight controller limits.

## 1. Central open design choice for owner/SA

**What does `ACTUATION_ACTIVE` do during a tick without a new SIM_CONTROL_FRAME but before `frame_timeout_us`?** Proposed S1: retain the *most recent authorized* virtual intent while its frame and independent RF health remain fresh, but recompute state and output gates on every tick. No new arm edges, qualification or accepted-frame timestamps are generated by an empty tick. If the timeout boundary is exceeded, enter virtual `CONTINGENCY`, output null. This is **pure PC simulation** and MUST NOT be copied to real flight failsafe; flight policy is unapproved.

Alternative S2: emit null virtual output whenever no frame in that tick. Either choice can be deterministic. **Choose one before code handoff.** The P25 oracle table below indicates candidate S1 where relevant; it cannot be marked passed yet.
