## 1. Deliver a working integrated experience, not a 13th checker

A single offline Python command `scripts/demo.py --case nominal|recovery|conflict --view` and optional generated **local, static, offline HTML timeline viewer**. It composes real preflight/scheduler/normalizer/temporal/priority/health/triage APIs, applies an **independent, deterministic, stateful R1 behavior model** to valid v2 observations, computes TEST_ONLY model M0 effort and displays state/ARM/FAULT/left-right *effort bars* in timeline/playback. The viewer **must not** claim effort is physical servo position, wing beat Hz, lift, pose or control stability; any wing drawing is illustration only, not actuator geometry. The HTML has no network/remote data/serial/WebUSB/device API and cannot command any process. CLI returns real statuses and prints where trust is missing.

## 2. Mandatory separation of the modeled lane from operational authority

**Two entirely separate lanes, no implicit bridge:**

- **MODEL lane:** `modeled_state` may show `DISARMED`, `ARM_CHECK`, `ARMED_IDLE`, `ACTUATION_ACTIVE`, `CONTINGENCY`, `FAULT_LATCHED` **for explanation of the normative R1 transition algorithm**. All model-positive milestones use exact accepted *simulated* wire observations and frozen values, **not** TASK-006 synthetic PASS as a credential. A `model_effort_left/right_micro` pair is only a **counterfactual mathematical model request**; it is never an authorized output, R1 committed output, PWM/angle, or physical actuation. No actuator adapters.
- **OPERATIONAL lane:** current approved release has **no protected runtime trust root/allowlist**. Therefore always `runtime_authorized=False`, `actual_virtual_output=None`, `physical_output=None`, `output_allowed=False`, `control_trace_sha256=None`. An E2/E3 positive merely permits offline analysis; no scenario/CLI/user input can set authorization. A new trust-root provisioning/host-attestation contract and Owner decision are required before a later runtime may publish *authorized* virtual effort. **Never label this task R1 runtime PASS/COMPLETED.** `MODEL_REPLAY_COMPLETE` is permitted, not a `SimulationRunReportV2` completion claim.

For model tick records, keep two clearly different objects: `ModelTick` for modeled states/effort, and `R1TraceCandidateTick` for **schema/serializer conformance** with `output_allowed=false`, all `requested_*` and `left/right_micro_effort` null, `input_mode=NONE`, clips `[]`. Do NOT fabricate a normative R1 `COMPLETED` trace from only model ticks. Candidate header/tick/terminal tests are marked `DESIGN_CONFORMANCE_ONLY`, not actual trusted trace. Candidate serialization SHA may be named `candidate_trace_sha256` in test evidence, never `control_trace_sha256`. Do not call the candidate trace the R1 execution log or permit it to enter a publishing callback. 

## 3. Stateful R1 behavior model — precise ordered decisions

Implement an immutable `ModeledPrior` created only from BOOT genesis within the F1 model runner; advance once per 5000us tick in a **private model snapshot** following successful *internal* MODEL journal append. Carry: modeled SafetyState, committed tick, last accepted control ORIGINAL time, last uncontested HEALTHY RF ORIGINAL time, effective RF status+timestamp, held input F/S, first LOW original timestamp, qualified-LOW committed tick, HIGH-edge original timestamp/committed tick, recoverable simulated fault causes. Old E1 ledger and its snapshot must never be used to commit modeled positive acceptance; it is an unrelated F0 diagnostic lane. Accepting input in MODEL lane is *not* an authenticated production intake.

Tick algorithm: (1) one genuine TASK-001 v2 accepted scenario; (2) genuine TASK-002 chronological batch; (3) TASK-003 entire batch normalization preserving original IDs; (4) TASK-004 derived prior facts from **private model** snapshot; (5) TASK-005 provisional priority; (6) TASK-007 health evidence with private model prior RF; (7) TASK-008 triage diagnostics (its `TRUST_NOT_PROVEN` stays intact); (8) independent MODEL-only arbitration per frozen Design/115 + /116; (9) draft canonical record; (10) private complete append acknowledgment; (11) swap private model snapshot and display model result. If any upstream validation or append fails, no new row, output or state is displayed and no retry in same run.

R1 priorities and thresholds (do not silently change): catastrophe/latch > armed active RF/control hazard including when RESET simultaneous > prior CONTINGENCY hold except qualified recovery > RESET outside higher hazards > coherent LOW > ACK recovery with **previously committed** LOW and allowlisted resolved causes > HIGH edge/confirmation/demand > safe hold. BOOT at T0 -> SELF_TEST; later SELF_TEST -> DISARMED with RF UNKNOWN permitted (no ARM). LOW must be **two distinct accepted frames on different ticks** separated original timestamp >=20000us; LOW qualifies only after second tick commit; later HIGH requires prior qualified low and neutral F<=0.02, abs(S)<=0.05, healthy RF, clean control and a deliberate LOW->HIGH edge. HIGH confirmation requires a **separate later accepted frame**, original time minus HIGH-edge original >=100000us and neutral; then ARMED_IDLE. Only a later accepted HIGH with flap>0.05 and no hazards can enter model ACTIVE; F=0.05 exactly does not activate. Coherent accepted LOW disarms; active no-new-frame S1 holds only until BOTH independent accepted original control/RF freshness ages <=200000us; no timestamp refresh on empty tick. A valid UART observation with RF LOST is not trusted accepted control. `HEALTHY+LOST` same tick resolves LOST. Invalid UART or distinct valid conflict denies and breaks qualification; equivalent valid duplicates count once and retain all IDs. Catastrophe never clears within run. Qualified ACK in CONTINGENCY requires previously committed low, restored RF, every cause in approved recovery allowlist and no RESET on same tick; consumes LOW window and returns DISARMED; never automatically rearms.

Only six wire-v2 event kinds, no voltage/power/scheduler physical fault inventions. `VOLTAGE_WARNING_RECOVERABLE` cannot be generated by unsupported wire; do NOT invent schema v3. Numeric F/S from validated `int|Decimal` must convert exact base-10 millionths using `as_integer_ratio` or equivalent, never float rounding. `mix_m0` is the only calculation for model-effort pair. Clip tags sorted UTF-8 bytewise. `AirborneEstimate=UNKNOWN` always.

**Priority nuance:** Existing TASK-005 C1 and TASK-007/D2 are *provisional/diagnostic*, not full FSM or a trust arbiter. F1 may compute its independent MODEL transition under frozen R1 but must never reinterpret `TRUST_NOT_PROVEN` as operational PASS. All discrepancy tests compare MODEL rules vs Design/115 and flag collisions to SA rather than modifying old packages.

## 4. Candidate RFC8785 serializer and append-before-display

- Implement a **separate** testable RFC 8785/JCS encoder or use a reviewed, pinned, offline-installable package. Test UTF-16 key sorting (not naive Python Unicode code-point order), escaped Unicode controls, normalization invariance (none), I-JSON, negative zero, finite-number ECMAScript serialization boundary cases, and reject NaN/Infinity, unpaired surrogates, duplicate object keys and non-I-JSON numeric values. `json.dumps(sort_keys=True)` alone is insufficient.
- Schema-shape conformance using frozen `Design/contracts/G0A1_TRACE_RECORDS_R11_CANDIDATE.schema.json` and external report schema. Candidate no-authority ticks obey all-null fields when `output_allowed=false`; candidate is labeled `MODEL_TRACE_CANDIDATE_NOT_OPERATIONAL`. Compare exact bytes for P210 **hand-authored** minimal reference as a serializer vector (the engine/scheduler revision of that file is DESIGN-only and must not be claimed as executing build identity). Model's candidate header uses F1 model revision label, never design-reference engine revision.
- Candidate stream order is header, exactly one tick per model-committed eval, terminal (when model analysis finishes); hash is `candidate_trace_sha256` *only in offline analysis evidence*. No `control_trace_sha256` and no `SimulationRunReportV2.COMPLETED` from this task. A serialized terminal is merely a format-conformance vector, not runtime authorization.
- Do not emit an uncommitted model tick to console/HTML/JSONL. Use a bounded **internal** append primitive with deterministic fault injection (`BEFORE_APPEND`, `SHORT_WRITE`, `AFTER_WRITE_BEFORE_ACK`, `QUOTA`, `SERIALIZER`) in tests. Internal success = MODEL commit only, not R1 durable trace receipt; failed append is sticky and returns `MODEL_EVIDENCE_INCOMPLETE`, no retry. Offline file write uses same-process temp+replace only; no crash durability claim. All output is explicitly read-only diagnostics; viewer has zero output handlers to core.
- Bound 12001 ticks, 20000 scenario events, raw <=2097152 bytes, offline candidate/diagnostic bytes <=16777216. A reader may stream candidate records to avoid O(N^2) concatenation. Replaying identical bytes produces deterministic model/serialization results independent of locale, TZ and CLI wall clock.

### Identity and trace honesty

An arbitrary HMAC/manifest/hash supplied in CLI is not a trust root. No model success upgrades E2/E3 negatives into positive authorization. If exact runtime truth and model truth disagree, keep operational result denied. This Stage F1 supports **functional development before trusted deployment**, not production simulated control approval. To enable authorized virtual outputs later requires separate Owner decision and protected runtime trust provisioning; G2/G3/G4 and physical control still need independent reviews.
